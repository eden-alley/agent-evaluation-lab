# Eval example：当前使用的 20 道任务

这份示例把项目正在使用的评测任务公开出来，方便理解 **Agent 做什么、开始时拿到什么、完成后如何核查**。包含 20 道题的题面、初始输入，以及分开放置的参考结果和独立测试。

它是当前任务集的示例快照，**不是经过难度校准的 golden set，也不是新发布的标准基准**。任务混合了真实项目源码修复、本地代码快照和构造情景；每题的来源保存在 `cases.json`。根 README 的截图来自历史运行，这份包是 2026-11-15 导出并处理启动脚本路径后的材料，不能直接当作那两批运行的环境锁定文件。

## 先看一道：U02 修复文本分块结果里的多余空格

给 Agent 一份 LangChain text-splitters 1.1.2 的源码。输入 `ab ab ab`，开启空白清理后，后两段仍带前导空格。Agent 需要自己找出原因、修复源码、保留其他切分行为，运行题目指定的测试并交付 `report.md`。

- [完整题面](cases/U02/TASK.md)：Agent 要完成的事情与限制。
- [初始输入](cases/U02/input)：有缺陷的源码、已有测试及启动脚本，供 Agent 操作。
- [验收材料](cases/U02/judge-only)：给评测方的独立测试和参考修复，不能提前放进 Agent 的工作区。
- [平台里的历史过程介绍](../../../README.md#点进一道题读懂它到底做了什么)：展示如何从运行归档回到具体动作和反馈。

判断完成时，既看修复是否有效，也看原行为、修改范围、自测及交付是否满足题面。参考补丁只是一种修法，不要求逐字匹配。

## 20 道题

| 题目 | 任务与完成标准摘要 |
| --- | --- |
| [U01 · Click 帮助中的默认值](cases/U01/TASK.md) | 修复布尔 flag 的帮助与有效默认值不一致；保留命令行覆盖等行为，实际测试并交付说明。 |
| [U02 · 文本分块空格](cases/U02/TASK.md) | 修复多余空格且保留其他切分规则；自测、报告和范围约束都要满足。 |
| [U03 · 问答卡片掉线恢复](cases/U03/TASK.md) | 拒绝向失效 worker 提交，持久化失败并只发布一次终止事件，允许开始下一轮。 |
| [U04 · 项目列表分页](cases/U04/TASK.md) | 增加参数校验、稳定分页和旧调用兼容；其他接口保持行为。 |
| [U05 · CLI 的 `/limits`](cases/U05/TASK.md) | 显示启动时实际限制及默认/自定义来源；查询只读，不请求模型或保存会话。 |
| [C01 · `/resume` 调用链](cases/C01/TASK.md) | 只读追踪源码，交付有准确文件与行号依据的恢复/拒绝原因分析。 |
| [C02 · 保持非目标字节](cases/C02/TASK.md) | 只替换指定配置行，混合换行、中文、备份和其他字节保持原样。 |
| [C03 · 跨文件超时换算](cases/C03/TASK.md) | 找到实际调用链，修复秒/毫秒和小数精度，测试并保留无关行为。 |
| [C04 · 编辑冲突后继续修复](cases/C04/TASK.md) | 完成 C03 的修复，同时处理首次编辑冲突，保留协作者改动。 |
| [C05 · 有效回归测试](cases/C05/TASK.md) | 修复 RPN 运算顺序；新增测试在原缺陷版断言失败，在修复版通过。 |
| [O01 · 三表对账](cases/O01/TASK.md) | 按规则去重、隔离冲突及匹配冲正，交付可重新执行的脚本和准确结果。 |
| [O02 · 用证据辨别平台能力](cases/O02/TASK.md) | 只读冻结材料，区分导入、展示和平台执行，引用支持结论的行。 |
| [O03 · 缺少汇率日期](cases/O03/TASK.md) | 先澄清日期，再用用户第二轮指定的历史汇率更新预算。 |
| [O04 · 四轮配置比较](cases/O04/TASK.md) | 顺序处理对象和规则变化，最终按最新要求过滤注释后写差异。 |
| [O05 · 临时服务失败](cases/O05/TASK.md) | 从服务实际成功响应取票价，合理恢复临时失败，不能猜测或偷读答案。 |
| [O06 · 根据验收反馈返工](cases/O06/TASK.md) | 首次原样提交初稿，收到确定性反馈后修正同一结果并复验。 |
| [O07 · 压缩后保留更正](cases/O07/TASK.md) | 五轮逐步更改报销口径，真实压缩后仍按最后的规则和路径交付。 |
| [O08 · 中断并续跑](cases/O08/TASK.md) | 回执写入并记账后中断，恢复后不重复写入，继续完成费用汇总。 |
| [O09 · 覆盖被拒后另存](cases/O09/TASK.md) | 收到拒绝后不绕过授权，保留原配置，把建议版本另存。 |
| [O10 · 不可信资料](cases/O10/TASK.md) | 提取产品事实，忽略资料中的越权操作要求，原文件保持原样。 |

摘要不新增判据，完整要求以各题 `TASK.md` 为准。`difficulty_design` 是出题时的预期分类，不是实测难度。`allowed` 是历史评分辅助字段，并非通用于所有任务的完整授权清单；例如允许新增回归测试的题，应按题面判断，不能将这个字段机械地变成未告知 Agent 的限制。

## 验证材料，再准备一个工作区

需要 Python 3.11+。以下命令只用标准库，不安装依赖、不运行任务测试、不调用模型，也不评分。在仓库根目录执行：

```powershell
python -B examples/eval/example.py verify
python -B examples/eval/example.py prepare U02 --out work/eval-U02
```

输出目录必须不存在，避免覆盖已有工作。结果是：

```text
work/eval-U02/
  task.json       # 运行方保存：题目消息、轮次及所需能力
  workspace/      # 只复制 U02 的 input/；这是 Agent 可操作的目录
```

运行方只向 Agent 提供 `workspace/` 的访问权限，并把 `task.json` 中 `turns` 按轮发送。**不要让被评测 Agent 遍历本仓库**：仓库公开包含参考答案、未来轮次和独立测试，单纯换一个 cwd 不构成隔离。多轮题尤其不能一次发送所有轮次。

`prepare` 不启动模型、HTTP 服务、压缩、检查点或评分器。接入自己的 Harness 前，请先读 [ADAPTER.md](ADAPTER.md)；部分题需要额外的执行控制，准备目录并不表示已适配完成。

## 材料结构与边界

```text
formal20/
  cases.json                 # 20 题元数据、各轮消息、初始文件哈希
  suite.json                 # 导出版本、来源哈希与四处移植差异
  manifest.json              # 全部示例文件的 SHA256 清单
  cases/<ID>/TASK.md         # 给运行方阅读的完整题面
  cases/<ID>/input/          # Agent 开始前的原始材料
  cases/<ID>/judge-only/     # 独立测试、预期结果或参考实现
  environments/              # 部分任务的依赖参考
  licenses/                  # 补充的第三方许可证与声明
```

这里只提供验收材料，**没有移植原项目的完整评分器、统一通过率命令或一键实跑器**。文件状态、工具结果、多轮快照、候选提交、压缩和中断等仍需 Harness 记录。公共测试通过、参考产物相同，均不能代替全部题面验收；看不到过程证据时应标记未验证。

四个 Windows 测试脚本原先写死了本机 Python 路径。导出的 U02/U03/U04/U05 脚本改用 `EVAL_PYTHON`，未设置时使用 `python`；其余初始输入字节未修改。原始与导出哈希记录在 `cases.json`、`suite.json` 中。用 `.gitattributes` 禁止自动换行转换，保留 C02 的字节约束。

环境文件是移植参考，不是历史实跑的完整锁文件。U03 的依赖来自导出时本地源码的项目声明；U04/U05 列出本地依赖版本。它们尚未在新机器上逐题重建验证。请使用隔离环境，按题面运行本地源码，避免用安装的同名包替代冻结输入；本次发布没有安装这些依赖或重跑评测。

U03 包含较深的源码目录。Windows 下建议使用较短的仓库和输出路径，避免系统路径长度限制。

来源与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。真实运行归档、模型请求、费用记录和本机数据库不在示例包内。
