# 维度与证据：按具体任务选用

这是候选目录，不是所有 Agent 的统一能力标准。先确定本次要判断的性质、适用条件和要求来源，再选择证据与检查项。

| 维度 | 可以检查什么 | 证据重心 | 解释边界 |
| --- | --- | --- | --- |
| 结果质量 | 数值、事实、筛选、约束、内容质量是否满足需求 | 实际产物、来源资料、数据库或外部状态、独立复算 | 内部自洽不证明与原数据一致；完成声明不证明实际效果 |
| 交付完整性与可用性 | 交付物、格式、必要说明和可操作性 | 交付目录、文件全文、结构检查、路径与命令核验 | 格式正确可以与内容错误同时成立；允许不同合理排版与措辞 |
| 实现与执行过程 | 明确的实现约束、输入依赖、工具契约、反馈后的动作 | 代码查阅与实际调用分别记录；关联消息、工具输入输出、状态和版本 | 代码符合某性质不证明 Agent 当时怎样规划；不要强制唯一调用路径或隐藏思维过程 |
| 执行效率 | 实际时间、调用、Token、费用，以及可证实的无效动作 | 对应原运行的时间线、用量记录、调用与状态序列 | 合理核验和恢复不是浪费；无预算就不添加预算扣分；缺少必要性依据时保留未知 |
| 风险与约束遵守 | 授权、只读对象、允许的副作用、明确预算或停止规则 | 前后状态、完整操作记录、可靠隔离和权限证据、用量与停止事件 | “最后没变”与“过程中没写”不同；没有事件记录不自动证明事件没发生 |
| 交付物可复现性 | 固定输入和约定环境中能否重建交付物 | 独立工作副本、执行返回、重生成产物及输入标识 | 可以复现错误；不等于 Agent 主动自检或模型多次成功率 |

## 判断标准的三种来源

- **通用性质**：例如声明应与实际效果一致。仍需在本题中明确对象和可观察证据。
- **项目或任务约束**：例如 CSV 只读、一次纠正机会、文件名由用户指定。明确来源与适用版本。
- **可选实现策略**：例如采用某种规划格式、某个重试库或特定摘要方式。除非任务或架构契约要求，否则不能作为所有 Agent 的硬标准。

## 遇到缺证据时

| 情况 | 处理 |
| --- | --- |
| 数据正确，但没有过程记录 | 判定已能核验的成果；过程性质单独未知 |
| 原执行记录缺失，外部重跑通过 | 记录可复现性；不据此声称原 Agent 曾执行、自检或遵循全部过程约束 |
| 没有发生错误反馈或压缩条件 | 对应专项未测试或不适用；不记为专项通过 |
| 评分器异常、环境故障 | 记录评测侧故障；只对有独立充分证据的性质继续判分 |
| 完整交付目录显示必需文件不存在 | 文件交付要求为 0；不同于未采集到文件 |
| 要判断“从未发生某副作用” | 先核对审计覆盖或可靠隔离；只有末态不足时保持未知 |

效率诊断要尽量具体。例如疑似无效重复调用，需要同时检查输入和状态是否改变、上次结果是否仍可用、是否为合理重试或核验；不能只按重复命令字符串扣分。

一项能力在多个场景中表现一致才逐步增加外推依据。单题或同一批共享输入的成功不能自动代表跨任务泛化。
