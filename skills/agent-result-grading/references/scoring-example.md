# 共创范例：费用汇总的六维评分

这是首版方法的教学例，来自已讨论的构造交付。它有真实离线脚本复算和重跑，但没有真实 Agent 执行记录；语义标签未做独立多评测员校准。下文是便于随 Skill 携带的缩写，不是完整运行证据包。

## 任务与正确结果

合并两份费用 CSV，按 ID 去重，只纳入 2026 年 10 月、CNY、approved 的记录。退款抵扣，金额精确计算，原 CSV 只读。交付可运行脚本、JSON、中文 Markdown 和路径/运行说明。Markdown 包含分类、合计、去重数和排除原因。

两份导出共有 14 行；E003/E005 重复出现。以下为 12 条唯一记录：

## 构造交付与证据

有缺陷的交付使用 Decimal 计算，但对金额取绝对值，导致学习49.80、总额135.80。Markdown 缺少去重数。其余结构、统计、排除原因和交接说明符合要求。

实际取得最终文件、代码和交接说明。独立干净副本运行脚本成功，并生成相同报告；交付时两个输入 CSV 的哈希与初态一致。原 Agent 的调用过程、写入审计及用量没有提供。

## 分别汇总

| 维度 | 满足 / 不满足 / 未知 | 维度分 | 判定覆盖率 |
| --- | --- | --- | --- |
| 结果质量 | 6 / 2 / 0 | 75 | 100% |
| 交付 | 3 / 1 / 0 | 75 | 100% |
| 实现与执行过程 | 1 / 0 / 2 | unknown | 33.33% |
| 执行效率 | 0 / 0 / 2 | unknown | 0% |
| 风险与约束 | 1 / 0 / 1 | unknown | 50% |
| 脚本可复现性 | 2 / 0 / 0 | 100 | 100% |

过程维度已判定项通过率虽然是100%，完整维度分仍为unknown。脚本可复现性100分与金额错误同时成立，因为稳定复现错误结果也是可复现。

原任务必需要求中存在明确失败，任务验收为0，但仍保留各维度表现。R5/R7是同一退款符号缺陷的两个表现；D3是另一处交付遗漏；S2是证据缺口。

将退款改为抵扣并补全Markdown后，R5/R7/D3变为1。此时结果与交付维度均为100，其他维度不变。原任务验收变为unknown，因为S2仍未解决。不能把100%的已判定项通过率写成整体通过。

允许排除记录倒序，或用“状态不是approved”“币种为USD”等等价原因。不要按参考答案的固定顺序或字面措辞评分。

## 交接给开发的线索

- 交付脚本中的退款符号处理已有定位证据，可以修复并补退款回归。
- 报告缺项提示需要核对公开交付要求；若真实运行反复出现，再判断是否修改提示或验证策略。
- 缺少过程与效率证据时先取得基线，不猜测存在过度重试、规划不足或上下文缺陷。
- 这些是构造案例中的观察，不能作为真实 Harness 的已验证缺陷。

## 可计算输入

[example-checks.json](example-checks.json) 将上述标签表示为汇总输入。每项的 `applicable` 决定是否计入维度分母；`required_for_task` 决定是否参与任务验收；不适用项使用 `result: null` 并保留理由。`evidence_reference` 是教学说明定位，不等于真实 Trace。

在本 Skill 目录执行：

```text
python scripts/aggregate_scores.py references/example-checks.json
```

输出应与上表一致。这个操作只验证输入标签的聚合，不证明标签本身正确。
