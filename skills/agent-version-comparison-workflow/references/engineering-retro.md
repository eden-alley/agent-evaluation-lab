# 工程复盘：从现象选出下一步动作

仅在正式整批评测准备开发方向时，对证据指向的问题使用本清单，不要求每次评测产出建议，不必逐项填满。复盘提出环境和工程改进候选，不承担任务评分，也不证明根因。

1. **锁定事实**：哪道题、哪个指标退步或仍有缺陷？核对原始输入输出、停止原因和预算。工具报错、工具缺陷、Agent 忽略反馈是不同解释；预算耗尽也不证明曾有恢复机会。
2. **先查已有机制**：记录当时版本中的入口/配置/检查及其可见证据。分清“确认不存在”“存在但未接通或异常”“已提供但未有效利用”“尚不能判断”。没有找到文件不等于机制不存在。
3. **定位最小缺口**：导航和依赖是否难找？已有检查是否可复用？指令是否重复或失效？调用是否确实没有信息增益？关键日志和状态当时是否可见？只追查被证据触发的方向，同时保留模型决策和任务含糊等解释。
4. **选一个最小动作**：能机械检查的先复用已有检查；不能确定原因时先补证据。说明作用位置、复用机制和新增维护成本。可以删减冗余指令、改进材料入口，或明确暂不开发；不默认加工具、长提示词或新 Agent。
5. **给出反证方法**：固定任务、预算、模型及其他比较条件；写出期望改善的指标，以及不能退步的结果、范围和成本。单题复现只支持该问题；扩大结论需要更多题或重复运行。

最后只保留最多 3 条可执行、可验证的候选。不把“全部失败样本都加规则”当作开发路线；不为了让评测通过而追加定位提示、改变完成标准或删除约束。

字段用自然语言写清“事实 → 已有机制 → 缺口 → 最小动作 → 验证”。实现材料未进入证据目录时写“尚未核查”，不要伪造平台引用。输出仍使用主 Skill 的简短分析格式，不新增复盘表单或强制多 Agent 流程。

来源：Matt Pocock [retro Skill，固定版本](https://github.com/mattpocock/skills/blob/a7d038f6bf7f01b516408e95e2fb56e0b338fa6f/skills/engineering/retro/SKILL.md)。借鉴会话证据、已有检查优先、工具/指令成本和信息访问；这里是本项目的适配版，没有修改上游，也没有将其变成评分器。
