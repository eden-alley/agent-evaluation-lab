# 轻量能力分析 v0.9.0

本次用途由准备参数 `review_scope` 指定，默认 `focused`；不超过3题始终为小范围验证，只输出指标与关键过程。正式整批评测选择 `formal_batch`（且超过3题）才允许附整批建议。用途由程序保存，提交时强制校验；正式批次无新建议仍可为空，不要求原因。旧方法与历史报告保留原样。

CLI准备材料增加 `--scope formal_batch`；MCP增加同名用途参数 `review_scope`。页面在复制分析指令处选择用途，已保存报告显示其实际用途。仅有实际整批建议时展示开发方向。

当前流程：程序准备全部题的归档与原评分 → 自动生成完整指标升降表及关键题候选 → 外部分析者按需解释关键题，准备改进时可提出最多3条开发建议 → 程序核对引用并提交报告。候选来自质量退步、原任务失败/不确定、原样重复退步及任务不可直接比较；资源增长不自动算能力退步，重复判定存疑也不要求全量撰文。

v0.8 延续按需讲解，开发建议可省略或为空，不要求no_recommendation_reason。既有历史报告与可选旧字段保留，不改原评分。候选供选择，相似问题可选代表，没有固定题数；建议引用题和明确指定题必须讲清回复区间、动作、反馈和关键转折。其他题仍自动保存统计、原判据与证据，未展开候选单独记录。建议的已有机制、原因、成功信号与保护项改为可选补充；核心写明问题依据、优先理由、动作和验证方法，不补写未做的诊断。

首页以指标升降为主，有建议时才显示开发方向摘要；无效重复只显示次数和可比覆盖，点击后再展开逐题与逐次依据。方法正文、提供记录与版本集中在报告来源。开发详情先展示动作、问题、优先理由及验证方法，机制和原因按需展开。

## 无效重复调用（原样重复范围）

新建对比时程序从清单内事件与实际模型输入固定分析结果，按工具名与JSON参数完全相同识别额外调用，每次重复都与上一相同调用比较。首次不计。首版对read_file可在目标始终未变、旧结果在实际输入中可见、返回的实际可见内容相同且成功时确认无效；明确清理的上下文或修改后的脚本/测试输入支持必要重复。其余保留证据不足，任意Shell命令不自动判无效。

每次判定保存前后事件、文件指纹、所用请求行与本题相关工具结果摘录。共享请求日志在原清单内固定并按case过滤；超过支持大小或无法解析的输入不据此记零。对比只汇总双方轨迹完整、判据版本一致且候选均有明确结论的同题记录。模拟、旧对比未固定此分析或缺证据时不判断升降。跨工具等价重复始终单列未评估。

统计注册表升级saved-checks-0.3.0，过程判据exact-repetition-0.1.1；原6项质量指标及5项资源指标含义不变。独立过程指标以确认无效次数为主，次数越少越好，1/36→1/41不因分母变化算进步。历史报告不重算；使用旧归档新建对比即可固定新过程指标，无需重跑Agent或评分器。

## 方法正文与输出检查

MCP/CLI准备材料使用POST `/{comparison_id}/review-materials`，一次提供固定Skill正文、版本、哈希、提供时间/渠道和输出要求。v0.7另提供 `key_case_candidates`；默认 `explanation_case_ids` 为空，表示没有额外指定必讲题，建议引用题在提交时自动纳入检查。v0.6固定版本仍要求全部所选题讲解，更早版本默认1道代表题。CLI可重复指定 `--explain U05`，MCP可用 `explain_case_ids`。CLI另保存 `Skill正文.md` 与 `方法提供记录.json`。

提供记录由服务端保存，程序自动带入提交。缺少指定讲解、建议缺少直接证据，都会在追加记录前被拒绝。v0.6方法每条建议还要求priority_reason，原样保存分析者的优先理由，不再以固定泛化句代替。旧方法字段仍兼容；空可选字段不改变历史请求指纹。建议的 `evidence` 使用case_id/side/path及事件或检查项定位；服务端解析并保存原始摘录。原有统计与评分不变。

报告固定当时方法正文和输出检查结果，平台可查看。提供正文不等于分析者已阅读；“结构与引用通过”不等于语义、原因或模型遵循已验证。旧GET准备入口与旧提交继续兼容，历史报告未有提供记录时明确显示未记录，不追补当前方法。旧20题离线建议样例保留为历史材料，未补齐新流程的讲解与直接引用，不代表0.4.0模型输出验证。

目的：把已有归档变成逐指标升降、题目依据与少量开发建议。程序负责材料读取、统计、固定引用和一次提交；外部 Agent 只解释事实、取舍与待验证的原因。

本模块不调用模型、不运行评测或检查器、不修改原评分。上下文质量、跨工具等价重复、恢复质量、简洁度与工具策略等没有确认判据的维度保持未评估。Markdown导出也优先展示指标和建议，原样重复明细折叠保留。

## 使用

平台启动后，在仓库根目录：

```powershell
.\.venv\Scripts\python.exe scripts/capability_review.py prepare <对比编号> --out <材料目录>
.\.venv\Scripts\python.exe scripts/capability_review.py files <对比编号> --case U05 --side candidate --query events
.\.venv\Scripts\python.exe scripts/capability_review.py read <对比编号> --case U05 --side candidate --path events.jsonl --start 1 --lines 40
.\.venv\Scripts\python.exe scripts/capability_review.py submit --packet <材料目录>/packet.json --analysis <材料目录>/analysis.json
```

优先给分析者 `材料摘要.md`、`materials.json` 和已发布 Skill；需要时读取 `cases/<题号>.json` 或原件。完整 `packet.json` 由程序保管，不必让 Agent 整份读入。`analysis-format.json` 是程序生成的文档格式，分析不必处理提交信封。

MCP：同一连接中调用 `prepare_capability_review`，按需 `list_capability_materials` / `read_capability_material`，再 `submit_capability_review`。程序为该连接保管准备时的材料和修订状态；重连需重新准备。旧逐题接口仍兼容。

更新之前已经启动的 MCP 客户端需要重新连接以发现新增工具；CLI入口可以直接使用。MCP 的准备与回执只返回精简摘要，完整证据由程序保存并按需读取。

## 逐题过程讲解

任务过程讲解融入现有能力分析Skill，不新增独立Skill或分析阶段。对本次要求的题目分别讲清具体任务背景、模型回复区间、关键动作与反馈、完成情况和停止位置；合并连续查阅，异常题补充必要细节。开发建议可选；没有建议也不要求解释原因，不显示空建议卡或开发方向页签。

分析文档可选 `case_explanations`。每题包含 `case_id`、明确的 `focus`（baseline/candidate/comparison）、`background`、最多8段 `stages`、`result` 与限制条件。阶段含标题、正文和证据；结果含正文和证据。证据只填 `side`、材料路径及 `event_id` 或 `check_id`，普通文本也可指定行范围。程序解析行号、摘要、原件节选及事件所在的模型回复次数（只累计model_response），不让分析者编写材料UUID或哈希。

引用须属于固定清单中的该题及指定A/B侧；缺失或重复事件、错误检查项、来源混用会在写入前被拒绝。报告与逐题内容在同一事务保存，历史报告不受后续讲解影响。`explanation_coverage` 单独记录讲解题数，不与指标覆盖或题目记录收齐混为一谈。

未展开讲解的题目保留原统计与自动摘要；新报告不自动继承旧报告的讲解。原有不含讲解字段的输入与历史提交编号仍兼容。

`examples/capability-review/u05-explanation-offline.json` 是正式20题中CLI限制查询任务的离线讲解样例，仅深入讲解真实B运行。它保留功能通过、报告完成、原测试被改动及README越界的各项事实，也保留自测项自动值0与复核后有效值1的历史，不做新的判分。

平台详情先展示一句结论及具体任务背景，再按回复区间展示经过，最后展示验收细节；result.text首段为结论，后续段落为验收，依据按需展开；原题、判据、资源和原始材料仍可查看。事件预览省略文件指纹清单，保留固定原件哈希、行号及可回查的原始节选。默认Skill正文只包含必要指引和短retro清单，完整案例与取证JSON保留在参考文件中。

原“评测”详情页也复用同一份讲解，默认进入“任务过程”，替代原先“执行轨迹与交付文件”的平铺阅读。程序按运行编号、题号和A/B范围查找最新相关报告，核对记录与被引用原件；没有本题讲解时只显示现有任务和确定性结果摘要，不补造过程。原始事件、交付文件保留在展开入口，展开时才读取；评分、Judge与独立重评位于“本题结果”等已有入口。没有增加新Skill、分析产物或全量讲解要求。只读接口为 GET `/evaluation-runs/{run_id}/cases/{case_id}/explanation`。

打包器使用与平台相同的 `SkillContent` 归一化正文，再计算哈希和字符数，避免末尾换行导致导入后的哈希变化。API导入、发布与引用链路有回归测试。更新前已连接的MCP客户端需重连以刷新可选讲解字段。

成功后保存 `receipt.json`、`report.json` 与 `指标升降表.md`（有建议时附建议）。没有回执时不能宣称平台已收到。

## 指标口径

注册表：`backend/lab/comparisons/metrics.py`，版本 `saved-checks-0.2.0`。修改分组或统计含义时必须升级版本；历史报告保存统计、逐题证据和口径，不随新代码重算。

| 指标 | 原归档字段 |
| --- | --- |
| 原任务整体完成 | core_acceptance；要求双方必需检查ID/规则一致，且为明确pass/fail |
| 代码任务独立回归 | independent |
| 最终代码有效自测 | agent_tested_final_change / agent_tested_final |
| 任务修改范围遵守 | scope / protected_files |
| 明确报告交付 | delivery / report / change_report |
| 显式定位说明 | localization |

每题每指标只计一次；同一指标多个对应检查全部通过才计该题通过。只使用两版同题、同检查ID集合、同规则且有效的0/1结果。缺项、规则变化、无效或未知结果排除并说明，未适用题不计零。原整体完成只是原判定的统计，不是新的端到端裁决。

资源包括模型请求、归档tool_call数量、归档失败tool_result数量、累计输入/输出tokens与题级耗时之和。只比较双方都有有效计数的同题记录。资源不是能力分；累计tokens不是峰值上下文，耗时之和不是批次挂钟时间。

平台分别显示质量覆盖、资源覆盖和未评估维度。收齐全部题目记录不意味着全部维度已经评估。净改善也必须展示具体回归题；不合成跨维度总分。

## 可靠提交

程序信封包含材料包哈希、固定Skill版本、准备时的报告/逐题修订和确定性请求编号。分析文档只包含摘要、最多3条建议和限制条件。建议通过指标ID和适用题目关联证据。

- 严格原件扫描在写事务之前完成，一次请求内复用；列表、历史报告和目录读取不重复扫描。
- 一次事务追加全部逐题记录和整体报告，任何错误回滚全部写入。
- 相同材料包及分析的重复提交返回原回执；相同编号不同内容返回409。
- 准备后有人提交新分析则返回409，不静默替换较新工作。新材料包需要重新分析确认。
- 原件改变时拒绝新的报告；已有报告与节选仍可查看，并显示最近完整校验状态和时间。
- 超时与非JSON响应分别报告，写入状态保持“尚未确认”；不自动重试、不自动换请求编号。

## 离线样例与边界

`examples/capability-review/real20-offline-analysis.json` 是针对现有两次20题真实归档离线整理的建议，不是LLM Judge输出。提交样例时使用 `--origin offline_program`，页面会明确显示程序统计及离线建议。

该样例原整体完成11/19→13/19，范围遵守20/20→16/20。O07的pass→unknown不计退步；资源仍包含20题。两次请求预算30→60且其他运行条件也改变，只支持本次归档表现，不能证明稳定能力或单个Harness改动的因果。

retro适配版只用于核查已有机制、实际缺口和最小验证动作。未核查的实现写“尚未核查”；原因状态只允许待验证或未确定，不把问题现象当作责任归因。自动统计已通过离线验证，模型遵循Skill的质量未做调用或校准。
