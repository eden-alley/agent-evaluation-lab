# 保存交付物的独立检查

首版支持固定任务版本的 U05（Click 8.1.7 默认值帮助问题）。它在已有归档上增加检查程序关联和独立检查记录；原数据集、Agent 执行、旧自动评分、旧复核均不覆盖。现有 archive/mock Judge 流程保持独立，没有接入新的 LLM 调用。

## 页面操作

进入真实运行的 U05 详情，任务介绍下面有“检查程序与重新检查”。首次关联检查程序后，点击“重新检查旧交付”。页面保留检查历史，逐项对照历史判定和本次判定，链接到原证据或本次测试证据。

检查未完成与任务未通过分别显示。原归档后来变化时，已保存的检查历史和新测试证据仍可读，并警示它们对应的是旧快照；变化后的输入不能沿用旧绑定重新检查。

## 接口

- GET `/api/v1/evaluation-runs/{run}/cases/{case}/checker`：支持的检查程序、已有绑定和检查记录列表。
- POST 同级 `/checker-bindings`：`request_id`、`package_id`、`package_version`。首版登记 `click-help@1.0.0`；任务内容摘要必须与登记的 U05 完全一致。
- POST `/api/v1/evaluation-runs/{run}/check-runs`：`request_id`、`binding_id`。
- GET `/api/v1/evaluation-runs/{run}/check-runs/{id}`：状态、独立报告、原输入当前是否仍有效。
- GET 同级 `/artifact?path=public.json` 或 `external.json`：仅返回报告登记且哈希一致的本次测试证据。

重复的同内容请求返回同一记录；并发情况下仅插入者安排执行。相同请求编号改变内容会拒绝。服务重启中断的工作明确标记 failed，不悄悄重跑。

## 版本与执行边界

绑定保存任务定义摘要、数据集引用、完整原运行与清单摘要、所需输入摘要、检查包摘要、检查表和执行环境身份。包摘要涵盖 checker/archive/worker/sandbox 和受信测试文件。运行时核对已加载版本与磁盘代码，更新程序后需要重启服务；旧绑定不能执行新的包。Python、原生 Codex exe 的身份也保留。正式发布修改须升级包版本；开发中的内容差异同样由哈希区分。

评分逻辑、公开测试和独立参数矩阵是项目内登记的受信代码，不导入归档中的可执行评分脚本，不导入当前被测 Harness。交付物和原始日志只经清单及哈希校验后读取。两个测试套件分别在短路径临时副本里运行，副本中恢复受信测试；原有文件范围检查使用未经替换的原始快照。

执行器只通过 Windows MXC 原生命令沙箱运行固定检查入口，没有宿主直接执行回退，没有模型客户端。每个套件最多60秒，输出上限4MiB；子进程只继承必要系统变量。临时 Agent 脚本会作为原产物保留，但不会被作为检查入口执行。独立检查目录在数据库同级 `check-runs/{id}`，不写回原归档。

测试断言失败或交付代码导入/运行错误意味着行为检查未通过。执行器、环境、检查协议错误意味着检查任务未完成，不产生全零成绩。缺少过程证据保留 unknown。

`self_test` 只看原执行记录中对应最终源码、完整公开测试目录的成功自测；零测试、跳过或过滤后的测试不据此算成功。观察记录缺失或不完整时保留 unknown。外部重跑不补成原 Agent 主动自测。`repeatable` 对照原成功公开自测，没有比较基准时 unknown，不因功能失败自动判不可复现。语义项不会复制历史 AI 标签来冒充新判定。

## 首版范围

这是一条任务的可执行接口试点，不是完整基准套件，不代表 Judge 已经校准。非 U05 任务尚未登记检查程序。当前能力页的历史 Judge 分析不会被独立检查记录自动覆盖；接入新分析属于后续范围。
