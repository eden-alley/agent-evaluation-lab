# Skill 后续共创交接

## 已确认的方向

用户在外部 Coding Agent 中提出需求，由它调用平台、按需读取已发布 Skill，生成评测集草案和质量报告；用户在网页审阅并确认版本。

Skill 是核心能力，其方法内容必须与用户共同设计，不能由 Agent 独自定稿。当前内置“评测集设计”只有待共创目录项，没有正式方法内容。

## 待讨论的首版建议

建议先设计三个 Skill：评测集设计、评测集质量审查、一个具体业务 Skill。这是讨论建议，不是已确认的方法或开发规格；首个业务领域仍需用户确定。

先用一个真实小需求共同推演职责、输入、输出和质量依据，再编写内容。审查需同时检查漏报、误报与证据是否成立。接口测试通过不证明 Skill 生成质量。

## 新对话先读

1. `PRODUCT.md`：最新产品方向与方法所有权。
2. `docs/EXTERNAL_AGENT.md`：对外流程和约束。
3. `docs/FRAMEWORK.md`：真实能力与示例能力边界。
4. `backend/lab/quality_schemas.py`：实际输入输出合同。
5. `backend/lab/mcp_server.py`：可调用工具。
6. `VERIFICATION.md`：验证证据与未完成项。

如果合理的方法无法通过现有接口表达，记录差距并向用户提出建议，不擅自改平台代码。新付费模型调用需要单独说明用途和请求/费用上限并取得批准。不要擅自发布正式 Skill、改被测 Harness 或客户端全局配置。

当前真实评测执行、评分与运行比较尚未接入；相关页面结果仍是明确标记的示例。
